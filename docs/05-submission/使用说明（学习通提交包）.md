# CampusSwap 文档管理平台 —— 看这份就能看懂也能跑起来

> **课程作业提交说明**（学习通）　｜　作者：Zyaire　｜　仓库：`RizzyZyaire/campusswap-doc-platform`
> 这是一个**单位内部文档管理平台**（Markdown 文档的创建 / 检索 / 审核 / 治理 + RBAC 权限体系）。

## 1. 想跑起来看真实效果（约 15 分钟）

**环境要求**（版本是我本机实测通过的）：

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | **17**（21 也可以） | 后端编译目标 17 |
| Maven | 用仓库自带的 `backend/mvnw.cmd` | 无需单独安装（首次会联网下依赖） |
| MySQL | **8.0+** | 建库建表脚本在 `backend/sql/` |
| Redis | 5.0+ | 登录 token 与权限缓存用（端口 6379） |
| Node.js | **≥ 20**（我用 24） | 前端 Vite 6；包管理用 pnpm（`npm i -g pnpm`） |

**五步命令**（Windows PowerShell，逐条复制）：

```powershell
# ① 建库建表 + 种子数据（45 篇文档 / 39 个权限点 / 3 个演示账号）
cd <解压目录>\backend\sql
mysql -uroot -p < schema.sql
mysql -uroot -p campusswap_db < data.sql
mysql -uroot -p < create-app-user.sql        # 建应用账号 campusswap_dev（最小权限，只给 CRUD）

# ② 起后端（dev 端口 10087）
cd <解压目录>\backend
$env:JAVA_HOME='<你的 JDK17 路径>'
$env:DB_PASSWORD='CampusSwap@2026'           # 见下方"两个 DB_PASSWORD 的区别"
.\mvnw.cmd spring-boot:run

# ③ 起前端（dev 端口 5173，/api 已代理到 10087）
cd <解压目录>\frontend
pnpm install                                  # 首次约 1~3 分钟
pnpm dev

# ④ 浏览器打开 http://localhost:5173
# ⑤ 用下面的演示账号登录
```

**演示账号**（`data.sql` 灌入的 bcrypt 真实哈希，可直接登录）：

| 账号 | 密码 | 角色 | 能看到什么 |
|---|---|---|---|
| `admin` | `Admin@123` | SYS_ADMIN（39 个权限点） | 全部功能：用户 / 角色 / 权限树 / 组织架构 + 文档治理 |
| `docadmin` | `Doc@123456` | DOC_ADMIN（20 个） | 审核队列、归档、驳回、分类与标签维护、全平台治理列表 |
| `staff` | `Staff@123` | STAFF（11 个） | 建文档、编辑自己的、检索、派生、收藏、回收站 |

**建议演示路线**（三条角色旅程，`docs/03-qa-review/TEST_CHECKLIST.md` 有逐页验收表）：
`staff` 登录 → 工作台 → 新建文档 → 提交发布 → 检索关键词 → 详情 → 收藏 → 我的文档；
换 `docadmin` → 审核队列 → 驳回并写理由 → 归档；
换 `admin` → 角色管理勾权限 → 组织架构绑角色 → 用户管理。**权限改动立刻生效**（旧 token 无需重登）。

> ⚠️ **两个 `DB_PASSWORD` 的区别**（我第一次换机器时踩过）：
> 应用读 `DB_PASSWORD` 当作 **`campusswap_dev`** 的口令（默认 `CampusSwap@2026`）；
> 而仓库里的机检脚本用 **`MYSQL_ROOT_PASSWORD`** 当 root 口令。别在同一个终端里混用。

## 2. 这个作业做了什么（一句话 + 数字）

- **8 个用户故事 / 24 条 BDD 断言**全部落地，每条都有可复跑的通过记录；
- **57 个后端接口**（系统域 25 + 文档域 30 + 文件 1 + 统计 1），14 张表 / 27 个索引，**无外键约束**（逻辑外键 + 代码校验）；
- 四道鉴权关卡：登录拦截器 → ThreadLocal 上下文 → `@RequiresPermission` 切面 → Service 属主校验（防 IDOR）；
- 文档状态机 9 种流转全分支（草稿 / 发布 / 编辑 / 派生 / 驳回 / 归档 / 删除 / 恢复 / 彻底删除），每次写入留版本痕迹；
- 检索走 MySQL **ngram 全文索引**（中文 2-gram），列表接口用 DTO 投影，**列表 SQL 不读大文本**；
- 性能：**每个读接口的 SQL 条数是常数**（18 个接口 × 2 种数据量逐一点数，零 N+1）；2 万篇数据量下高频查询与三档排序**全部命中复合索引、0 次 filesort**。

## 4. 想看代码，从哪读起（15 分钟路线）

`docs/02-design/CODE-TOUR.md` 是完整的"代码导读"，最短路线是：

1. **数据模型**：`backend/sql/schema.sql`（14 张表，每列都有 COMMENT）→ `docs/01-requirements/GLOSSARY.md`（字段唯一真源）；
2. **实体规矩**：`entity/BaseEntity.java`（审计列 + 逻辑删除 + ID 序列化成字符串）→ `entity/Document.java`（写 ID、读关联）；
3. **一条写链路**：`DocumentController.create` → `DocumentServiceImpl.create`（事务 / 校验 / 版本留痕）→ `DocumentRepository`；
4. **一条读链路**：`GET /api/documents`（检索）→ `DocumentQueryRepositoryImpl`（Criteria 动态条件 + 原生全文分页 + `orderBy` 白名单）；
5. **鉴权四关**：`common/security/{LoginInterceptor, SecurityContext, PermissionAspect, RequiresPermission}` + Service 里的 `assertOwnerOrManage`；
6. **前端一条链**：`views/document/DocumentEditView.vue`（md 分栏预览 + 图片上传 + `versionNum` 冲突横幅）→ `api/request.ts`（统一拦截器）。

## 6. 常见问题

| 现象 | 原因与处置 |
|---|---|
| 启动报 `Access denied for user 'campusswap_dev'` | 没跑 `create-app-user.sql`；或终端里残留了 `DB_PASSWORD`（那是 root 的口令） |
| 前端 `pnpm install` 慢 | 换国内镜像：`pnpm config set registry https://registry.npmmirror.com` |
| 5173 打不开但后端在跑 | 端口被占：`pnpm dev -- --port 5174`；前端 `/api` 代理已在 `vite.config.ts` 配好 |
| 登录一直 401 | Redis 没起（token 存 Redis）或数据库没灌 `data.sql` |
| 页面能开但列表空 | 说明库是空的：重跑 `data.sql`（幂等，会先 TRUNCATE 再插入） |
| 想恢复演示初始状态 | `mysql -uroot -p campusswap_db < backend/sql/data.sql` |
| 想看接口文档 | 用 Apifox/Postman 导入 `docs/02-design/openapi-campusswap.json`（57 个端点） |
