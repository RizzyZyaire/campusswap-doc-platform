# 符合度说明（对照老师《作业说明》）

> 项目：**CampusSwap 师大文档管理平台**（后端 Spring Boot 4.1.1 + Java 17；前端 Vue 3 + TypeScript + Vite）
> 本文件逐条对照《项目作业说明》的"需要完成的功能模块"，给出**实现位置**与**可复现证据**。

## 一、如何启动

| 步骤 | 命令 |
|---|---|
| 1. 中间件（原生安装，无需 Docker） | MySQL 8.0.46（3306）、Redis（6379）、Elasticsearch **9.4.5 + analysis-ik**（9200）、RabbitMQ **4.0.9 + Erlang/OTP 27.3.4**（5672 / 管理台 15672） |
| 2. 建库 | `mysql -uroot -p < backend/sql/schema.sql`，再 `< backend/sql/data.sql`（库名 `campusswap_db`，**15 张表**） |
| 3. 后端 | `cd backend && ./mvnw spring-boot:run`（dev 端口 **10087**；也可用 IDEA 直接 Run `CampusSwapApplication`） |
| 4. 前端 | `cd frontend && npm install && npm run dev`（端口 **5173**） |

**演示账号**（密码为 bcrypt 哈希存储，非明文）：`admin / Admin@123`（系统管理员）、`docadmin / Doc@123456`（文档管理员）、`staff / Staff@123`（普通员工）。
**演示数据**：45 篇文档（其中 **28 篇已发布**、可被 ES 检索到）、4 个分类、20 个标签、39 个权限点 / 3 个角色。

## 二、逐条对照

### 1. 项目骨架（Spring Boot 结构、统一响应、参数校验、全局异常、Spring Data JPA）

| 要求 | 实现 | 证据 |
|---|---|---|
| Spring Boot 项目结构 | `backend/src/main/java/com/campusswap/`，按模块分包 `system/`（用户·角色·权限·部门·日志）+ `document/`（文档·分类·标签·检索），`common/` 放通用能力，`entity/` 顶层 | 包结构一眼可见 |
| 统一响应格式 | `common/api/ResponseResult.java`：`{code, message, data}`；分页统一 `PageVo`、分页入参统一 `PageDtoReq`（含深分页保护） | 任意接口返回体 |
| 参数校验 | 全部入参 DTO 用 `@Valid` + 中文提示（如 `@NotBlank(message = "分类名称不能为空且不超过64个字符")`）；枚举白名单用 `@Pattern` | `document/dto/CategoryCreateDtoReq.java` |
| 全局异常处理 | `common/exception/GlobalExceptionHandler.java`：业务异常 / 参数校验 / 类型不匹配 / 数据完整性 409 / 方法不支持 405 / 兜底 500，**响应体绝不暴露堆栈与内部类名** | 故意传错参数即验证 |
| Spring Data JPA | 15 个实体（`entity/`）+ 仓储（`*/repository/`），动态条件走 `JpaSpecificationExecutor` + Criteria（**禁字符串拼接 SQL**） | `system/repository/OperationLogSpecifications.java` 等 |

### 2. 数据库（自行设计数据表，JPA 实体映射与访问）

- 建表脚本 `backend/sql/schema.sql`：**15 张表**（系统域 8 + 文档域 6 + 运维域 1：`sys_operation_log`），23 个索引，**零物理外键**（逻辑外键由机检 `verify-db-deep.ps1` 守），每列带中文 `COMMENT`，审计列统一 `created_at / created_by / updated_at / updated_by / deleted`。
- 种子数据 `backend/sql/data.sql`：39 个权限点三层树 / 3 角色 / 3 部门 / 3 账号 / 4 分类 / 20 标签 / 45 文档 / 99 版本留痕 / 39 收藏。
- 实体↔实库逐列对齐由 `--spring.jpa.hibernate.ddl-auto=validate` 启动验证 + 机检 `verify-db-deep.ps1`（9 项：DDL↔实库逐列 diff=0、15 组逻辑外键孤儿 0 行、审计列行为实测）守护。

### 3. 功能模块的 CRUD（至少两个核心模块：增删改查 + 分页列表）

**实际做了 7 个模块、64 个接口**（清单见 `docs/02-design/API_SPECIFICATION.md` §3）：

| 模块 | 接口数 | 说明 |
|---|---|---|
| 文档 | 15 | 增删改查 + 发布 / 审核 / 驳回 / 归档 / 恢复 / 彻底删除 / 派生 / 收藏 / 版本历史，含回收站与状态机 |
| 分类 | 4 | 树形增删改查 |
| 标签 | 4 | 增删改查 + 打标签 |
| 用户 | 6 | 增删改查 + 启停 + 重置密码 |
| 角色 | 6 | 增删改查 + 授权 + 查权限 |
| 部门 | 6 | 树形增删改查 + 绑角色 |
| 权限 | 4 | 权限点树查询与维护 |
| 检索 | 5 | 全文检索 / 引擎状态 / 重建任务提交·查询·最近 |
| 操作日志 | 2 | 组合条件分页查询 / 筛选下拉 |

分页一律走 `PageDtoReq`（`pageNum` 1~100、`pageSize` 1~100，越界返回 400 不静默纠正）+ `PageVo`。

### 4. 登录认证（密码加密 / **JWT 登录** / 登录状态存 **Redis** / 退出后 Token **立即失效**）

| 要求 | 实现 | 证据（实测） |
|---|---|---|
| 密码加密存储 | BCrypt（`config/PasswordEncoderConfig.java`），库中只有 `$2a$…` 哈希 | 机检 `PasswordHashCompatTest` |
| **JWT 登录** | `common/security/JwtService.java` + `system/service/impl/TokenServiceImpl.java`：**HS256** 签名，claims `iss=campusswap / sub=userId / jti / iat / exp`（2 小时）；密钥 <32 字节直接拒绝构造；**prod 只读环境变量 `JWT_SECRET` 且不给默认值** | token 实测 205 字符、3 段、`{"alg":"HS256"}`；**篡改 payload → 401** |
| 登录状态保存在 Redis | 签发同时写 `login:token:{jwt原文} → userId`（TTL 与 JWT 一致）+ `user:tokens:{userId}` 集合 | `redis-cli keys "login:token:*"` 实测 41 个键（值=userId、TTL≈2h） |
| 退出后 Token 立即失效 | 登出 / 停用 / 改密 → `DEL` 对应 Redis 键；校验顺序 = **先本地验签、再查 Redis** | **登出后同一 JWT 再访问 → 401**（签名仍有效，靠 Redis 撤销） |

### 5. RBAC 权限（角色、权限管理；用户分配角色、角色分配权限）

- 39 个权限点三层树（DIR 目录 / MENU 菜单 / BUTTON 按钮），3 个内置角色（STAFF 11 / DOC_ADMIN 20 / SYS_ADMIN 39），用户↔角色、角色↔权限、用户直授权、部门↔角色四张关联表。
- **四道鉴权关卡**：① `LoginInterceptor` 认证 → ② `SecurityContext` 线程上下文 → ③ `PermissionAspect` 功能权限（`@RequiresPermission("doc:publish")`）→ ④ Service 内归属/防 IDOR 校验。
- 权限合并压成**一条 UNION SQL**（用户直授 ∪ 角色权限 ∪ 部门继承角色），缓存 30 分钟 + **事务提交后失效**（`TxUtil.afterCommit`）；实测"给角色加权限后，旧 token 立即可用；撤销后立即 403"。
- 证据：`verify-m3.ps1`（36 项）+ `verify-m3-http.ps1`（142 项，含越权 403 断言）。

### 6. 操作日志（AOP 记录重要写操作 + 提供日志查询）

| 要求 | 实现 |
|---|---|
| AOP 记录 | `common/log/OperationLogAspect.java`：切**控制器包**且只记 `POST/PUT/DELETE`（不是逐个接口加注解——漏加一个就漏一条审计）；模块/动作优先取 `@OperationLog(module, action)`，否则按路径关键词与 HTTP 方法推断 |
| 记录内容 | 操作人（ID + 账号）、模块、动作、HTTP 方法、URI、目标 ID、中文摘要、**入参摘要（`password/token/secret` 打码 `***`、截断 1000 字符）**、IP、成败、失败原因、耗时 |
| 不影响业务 | `finally` 记录 + 整体 try/catch；落库**异步**（`operationLogExecutor`，有界队列 1000 + `CallerRunsPolicy`）；审计列在请求线程显式带走（异步线程没有 ThreadLocal） |
| 日志查询 | 表 `sys_operation_log`（第 15 张，19 列 + 3 索引）+ `GET /api/logs`（账号/模块/动作/成败/时间范围组合筛选 + 分页）+ `GET /api/logs/filters`；权限沿用 `sys:center`（**不新增权限点**，保持 39 个口径）；前端页面 `/admin/logs` |

证据：`verify-m14.ps1`（31 项，含"真做一次写操作 → 日志里必须出现这一条"）+ `Ac09OperationLogTest`（5 例）。

### 7. 全文搜索（ES 索引 / 关键词搜索 + **组合查询条件** + **结果高亮**）

- `document/search/`：索引实体 `DocumentSearchIndex`（`title/summary/content` 用 **ik_max_word 索引 + ik_smart 检索**，`categoryId/status/tags/*Name/时间` 用 keyword）、仓储 `DocumentSearchRepository`（`ElasticsearchOperations` + `NativeQuery`）、服务 `DocumentSearchServiceImpl`、高亮工具 `SearchTextHighlighter`。
- **关键词**：`multi_match` 字段权重 `title^3, summary^2, content`；**检索范围**：`TITLE` / `CONTENT` / `ALL` 三种可切换。
- **组合查询条件**：检索范围 + 分类 + **时间范围**（按 `publishAt`）+ **标签**（`tags` 多值精确匹配），全部放 `filter` 上下文（不打分、可利用缓存）。
- **结果高亮**：后端转义后插 `<mark>`，前端白名单渲染；实测"实习**支教**安全管理与应急处置预案"。
- **ES 不可用时自动降级** MySQL 引擎并在界面标出（老师机器上没装 ES 也能演示其余功能）。
- 证据：`verify-m8.ps1`（44 项）。实测收敛：仅关键词 8 条 → 2026 全年 8 → 2026-09 单月 6 → 2030 不可能区间 **0** → 假标签 **0**。

### 8. 异步索引重建（提交任务 → **RabbitMQ 后台消费执行**）

- **拓扑**（`config/MqConfig.java`）：`campusswap.search.exchange`（direct）→ 业务队列 `campusswap.search.rebuild`（绑死信交换机）→ 失败消息进 `campusswap.search.dlx` → `campusswap.search.rebuild.dlq`。
- **生产者**：`POST /api/search/rebuild` 只"下单"——落任务（Redis，2h TTL + 最近 20 条）+ 发一条消息（只带 taskId），**实测服务端 3~17ms 返回 `SUBMITTED` + 全局唯一 `taskId`**（课件验收要求 20ms 内）。
- **消费者**：`document/search/mq/SearchRebuildConsumer.java`，`@RabbitListener(ackMode = "MANUAL")`，重建成功后 `basicAck`；异常 `basicNack(requeue = false)` 进死信队列（**不原地重投**，避免队列堵塞）；**幂等**（任务已成功直接 ack 跳过）+ Redis 串行锁。
- **前端展示**：检索页「重建检索索引」按钮改为"提交任务 + 800ms 轮询"，界面完整显示 `已提交 → 执行中 → 已完成`（含同步条数与耗时）。
- **实测**：`RUNNING → SUCCEEDED`（28 篇 / 785ms）；故意停掉 ES 造错 → 任务 `FAILED` + **死信队列收到 1 条** + 主队列 0 条（无死循环）；停掉 RabbitMQ 重启应用 → **启动正常**、检索可用、提交返回 `FAILED` + 中文原因。
- 证据：`verify-m13.ps1`（32 项）+ `SearchRebuildMqTest`（6 例）+ `SearchRebuildTaskStoreTest`（4 例）。
